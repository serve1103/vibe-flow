# DevFlow 기획 모드 상세 스펙

> 훅: `devflow-prompt.js` (UserPromptSubmit)
> 목적: 코딩 전에 생각을 먼저 정리하게 만든다

---

## 1. 발동 조건

```
사용자 프롬프트 입력
     │
     ├─ "!" 접두사 → 스킵 (DevFlow 비활성)
     ├─ 빈 프롬프트 → 통과
     ├─ .devflow.json에서 planning.enabled: false → 통과
     │
     └─ Haiku에게 프롬프트 분석 요청
         ├─ docs/에 관련 설계 문서 있음 → 개발 모드 (통과)
         ├─ 단순 질문, 버그 수정, 리팩토링 → 개발 모드 (통과)
         └─ 설계 문서 없음 → 기획 모드 발동
```

---

## 2. 모드 판단 기준

### 2.1 프로젝트 상태 기반 (키워드가 아닌 문서 유무)

```
"로그인 기능을 만들고 싶어"
  → docs/에 로그인 관련 문서가 있나?
  → 있으면 → 설계 완료, 바로 개발
  → 없으면 → 설계 먼저 필요, 기획 모드
```

### 2.2 Haiku가 판단하는 항목

| 입력 | 분석 |
|------|------|
| 프롬프트 텍스트 | 작업 주제 추출 |
| CLAUDE.md (상위 50줄) | 프로젝트 기술 스택, 규칙 |
| docs/ 파일 목록 + 각 파일 제목 | 관련 설계 문서 존재 여부 |

### 2.3 Haiku 응답 형식

```json
// 개발 모드 (통과)
{"mode": "pass"}

// 기획 모드 (발동)
{
  "mode": "plan",
  "topic": "로그인 기능",
  "missing": [
    "인증 방식 (JWT/Session/OAuth)",
    "사용자 DB 스키마",
    "보안 요구사항"
  ],
  "concerns": [
    "비밀번호 해싱 전략이 필요",
    "세션 관리 방식에 따라 아키텍처가 달라짐"
  ]
}
```

## 3. 기획 모드가 하는 일

### 3.1 스마트 인터뷰

프롬프트에서 빠진 정보를 찾아 질문을 생성한다.

**질문 생성 규칙:**
- 프로젝트 컨텍스트(CLAUDE.md, docs/)에서 이미 알 수 있는 정보는 질문하지 않음
- 구현에 필수적인 결정사항만 질문 (nice-to-have 제외)
- 최대 5-6개 질문으로 제한

**예시:**
```
프롬프트: "결제 기능을 만들고 싶어"
CLAUDE.md: "PostgreSQL, Next.js 사용"

질문하는 것:
  - 결제 수단 (카드/페이팔/암호화폐)     ← CLAUDE.md에 없음
  - 결제 게이트웨이 (Stripe/Toss)        ← CLAUDE.md에 없음
  - 일회/구독 결제                        ← CLAUDE.md에 없음

질문하지 않는 것:
  - DB 종류                              ← CLAUDE.md에 PostgreSQL 있음
  - 프레임워크                            ← CLAUDE.md에 Next.js 있음
```

### 3.2 비판적 검토

작업의 잠재적 문제점, 위험, 고려사항을 분석한다.

**검토 기준:**
- 기술적 리스크 (복잡도, 성능, 확장성)
- 보안 리스크 (인증, 데이터 보호, 규정 준수)
- 설계 리스크 (기존 시스템과의 충돌, 의존성)
- 누락된 edge case

**예시:**
```
프롬프트: "주문 취소에 환불 기능 추가"

비판적 검토:
  - 이벤트 기반 추천: 동기 처리 시 타임아웃 위험
  - 멱등성 처리 필요: 중복 환불 방지
  - 환불 실패 시 재시도/알림 전략 필요
  - 부분 환불 지원 여부에 따라 DB 스키마가 달라짐
```

### 3.3 문서 갱신 요청

기획이 완료되면 docs/에 설계 문서를 작성하도록 요청한다.

**요청 순서:**
1. 사용자에게 인터뷰 질문
2. 답변 기반으로 설계 정리
3. docs/ 디렉토리에 설계 문서 작성
4. 설계 완료 후 구현 여부 확인

**문서 작성 기준:**
- 파일명: `docs/{주제}-design.md` (예: `docs/payment-design.md`)
- 내용: 결정사항, 아키텍처, API 설계, DB 스키마 등
- 이 문서가 존재하면 다음번에 같은 주제로 요청 시 개발 모드로 바로 진입

---

## 4. additionalContext 주입 형식

```
[DevFlow 기획 모드] 주제: {topic}

## 확인이 필요한 사항
다음을 사용자에게 질문한 후 진행하세요:
  - {missing_1}
  - {missing_2}
  - {missing_3}

## 비판적 검토
다음 우려사항을 고려하세요:
  - {concern_1}
  - {concern_2}

## 요청사항
1. 위 질문에 대한 답변을 받으세요
2. 답변을 기반으로 설계를 정리하세요
3. docs/ 디렉토리에 설계 문서를 작성하세요
4. 설계가 완료되면 구현 여부를 확인하세요
```

## 5. 상태 관리

| 파일 | 내용 | 기획 모드 시 |
|------|------|-------------|
| `.devflow/mode` | `"planning"` 또는 `"coding"` | `"planning"` 기록 |
| `.devflow/chain-step` | 체이닝 단계 (1-4) | `"1"`로 리셋 |
| `.devflow/pending` | 변경 파일 목록 | 초기화 |

- 기획 모드(`planning`) 동안 PostToolUse(개발 모드)는 스킵됨
- 사용자가 "구현하자"라고 하면 → 새 프롬프트 → 다시 Haiku 판단
- docs/에 설계 문서가 생겼으면 → `pass` → 개발 모드로 전환

---

## 6. 설정

```json
// .devflow.json
{
  "planning": {
    "enabled": true
  }
}
```

> Phase 1 한계: `enabled` 토글만 동작. `interview`, `critical_review`, `doc_update` 세부 토글은 Phase 2에서 구현 예정.

---

## 7. 비용

| 항목 | 비용 | 지연 |
|------|------|------|
| Haiku 모드 판단 | ~$0.001-0.002 | ~2-5초 |
| 프롬프트당 총 비용 | ~$0.001-0.002 | ~2-5초 |

기획 모드가 발동하지 않으면 (pass) 추가 비용 없음.

---

## 8. 제약사항

- Haiku의 판단이 100% 정확하지 않을 수 있음 (설계 문서가 있는데 못 찾는 경우)
- docs/ 파일명과 프롬프트 주제가 명확히 매칭되어야 정확도가 높음
- `!` 접두사로 언제든 스킵 가능 (이스케이프 해치)
- 프롬프트가 매우 짧으면 ("해줘") Haiku가 주제를 추출하지 못할 수 있음 → pass로 폴백
