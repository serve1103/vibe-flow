## 1. 시장 포지셔닝

```
            개인용                    팀용
           ───────────────────────────────────
직접 코딩  │ Cursor                  │ GitHub Copilot Enterprise
(개발자)   │ Claude Code             │
           │ GitHub Copilot          │
           │                         │
대화형     │ Lovable, Bolt           │ ← Vibe Flow
(비개발자  │ v0, Replit Agent        │   (이 포지션이 비어있음)
 포함)     │                         │
           ───────────────────────────────────
```

**Vibe Flow의 포지션: "팀을 위한 대화형 AI 개발 표준화 플랫폼"**

## 2. 경쟁 제품 비교

### 2.1 개인 대화형 도구

| | Lovable | Bolt.new | v0 | Replit Agent |
|---|---|---|---|---|
| **핵심 가치** | 대화 → 앱 | 브라우저 내 개발 | UI 생성 | 클라우드 IDE + AI |
| **타겟** | 개인 프로토타이핑 | 개인 빠른 개발 | 프론트엔드 | 개인 풀스택 |
| **팀 지원** | 없음 | 없음 | 없음 | 제한적 |
| **표준화** | 없음 | 없음 | 없음 | 없음 |
| **품질 보장** | 없음 | 없음 | 없음 | 없음 |
| **채널** | 웹만 | 웹만 | 웹만 | 웹만 |
| **백엔드** | 제한적 | 제한적 | 없음 | 있음 |

**이 도구들과의 차이:**
- 모두 **개인용** — 팀 표준화 개념 없음
- "빠른 프로토타입"에 최적화 — "일관된 품질"에 관심 없음
- 바이브코딩의 재현 불가능성 문제를 해결하지 않음

### 2.2 개발자 AI 도구

| | Cursor | Claude Code | GitHub Copilot |
|---|---|---|---|
| **핵심 가치** | AI IDE | 터미널 에이전트 | IDE 확장 |
| **타겟** | 개발자 | 개발자 | 개발자 |
| **팀 지원** | .cursorrules 공유 | CLAUDE.md | 조직 정책 |
| **표준화** | 규칙 파일 기반 | 규칙 파일 기반 | 제한적 |
| **품질 보장** | 없음 | 없음 | 없음 |
| **채널** | IDE만 | 터미널 + Channels | IDE만 |
| **비개발자** | 불가 | 불가 | 불가 |

**이 도구들과의 차이:**
- 모두 **개발자 전용** — 비개발자 접근 불가
- 규칙 파일(.cursorrules, CLAUDE.md)로 일부 표준화 가능하지만
  **품질 검증, 재시도, 블록 관리, 분석** 없음
- Vibe Flow는 Claude Code를 **대체하지 않고 위에 올라감**

### 2.3 오케스트레이션 도구

| | oh-my-claudecode (OMC) | Vibe Workflow | Vibe Coding Framework |
|---|---|---|---|
| **핵심 가치** | 멀티에이전트 오케스트레이션 | 5단계 파이프라인 | 검증 프레임워크 |
| **타겟** | Claude Code 사용자 | 바이브 코더 | 기업 |
| **팀 지원** | 제한적 | 없음 | 있음 |
| **블록/스킬** | 40+ 내장 스킬 | 없음 | 없음 |
| **커스텀 스킬** | 가능 | 불가 | 불가 |
| **품질 보장** | UltraQA | 없음 | V.E.R.I.F.Y. |
| **비개발자** | 불가 (CLI) | 불가 | 가이드 문서 수준 |

**이 도구들과의 차이:**
- OMC: 강력하지만 **개인 개발자용 CLI 도구**. 팀 블록 표준화 없음
- Vibe Workflow: 프로세스 정의만 있고 **실행 엔진 없음**
- Vibe Coding Framework: 문서/가이드라인이지 **실행 가능한 도구가 아님**

## 3. 차별점 요약

| 차원 | 기존 도구들 | Vibe Flow |
|------|-----------|-----------|
| **표준화 단위** | 규칙 파일 (텍스트) | 블록 (실행 가능한 캡슐화) |
| **품질 보장** | 없거나 수동 | 자동 품질 게이트 + 자가 회복 |
| **접근성** | 개발자 전용 | Creator (웹) + Consumer (Slack/텔레그램) |
| **재사용성** | 프롬프트 복붙 | 버전 관리된 블록 저장소 |
| **분석** | 없음 | 블록별 사용량, 품질 추세, 비용 |
| **팀 지원** | 규칙 파일 공유 수준 | 팀 블록 관리, 역할 분리, 공유 |

## 4. 기존 표준화 프레임워크와의 관계

### 4.1 V.E.R.I.F.Y. 프레임워크

Vibe Coding Framework의 검증 프로토콜. 블록의 **품질 게이트**와 유사한 철학.

**관계**: Vibe Flow의 품질 게이트 설계 시 V.E.R.I.F.Y.의 3단계 검증 레벨을 참고.
블록의 `fail_action`(retry/warn/block)이 V.E.R.I.F.Y.의 리스크 등급과 대응.

### 4.2 R.A.I.L.G.U.A.R.D.

CSA/Brighton Labs의 인지 보안 모델. AI 에이전트에 보안 추론을 내장.

**관계**: 보안 관련 블록(보안 리뷰, 취약점 점검)에 R.A.I.L.G.U.A.R.D.의 원칙을 적용.
블록 컨벤션에 보안 규칙을 포함.

### 4.3 OWASP Top 10

바이브코딩 환경에서의 보안 취약점 가이드.

**관계**: 코드 생성 블록의 품질 게이트에 OWASP 체크 항목 포함.
`custom_prompt` 게이트로 "이 코드에 OWASP Top 10 취약점이 있는가?" 검증.

### 4.4 Plan-Implement-Run

커뮤니티에서 수렴한 3단계 워크플로우.

**관계**: Vibe Flow의 블록 생성 대화가 Plan 역할. 블록 실행이 Implement.
품질 게이트가 Run(검증). 하지만 이 패턴을 사용자에게 강제하지 않음.

## 5. 위협 요인

| 위협 | 심각도 | 대응 |
|------|--------|------|
| Anthropic이 Claude Code에 팀 블록 기능을 네이티브로 추가 | 높음 | 개방형 블록 포맷으로 이식성 확보, 네이티브보다 빠른 혁신 |
| Cursor가 팀 표준화 기능 출시 | 중간 | Cursor는 IDE 종속. Vibe Flow는 채널 중립적 |
| OMC가 팀 기능 강화 | 중간 | OMC는 CLI 도구. 비개발자 접근성에서 차별화 |
| 기업이 자체 오케스트레이션 구축 | 낮음 | 범용 플랫폼 vs 맞춤 개발의 비용 차이 |

---

## 6. 핵심 경쟁 우위

1. **블록이라는 새로운 추상화**: 프롬프트보다 높고, 앱보다 낮은 수준의 재사용 단위
2. **Creator/Consumer 분리**: 만드는 사람과 쓰는 사람의 경험을 각각 최적화
3. **채널 중립성**: 같은 블록이 텔레그램, 디스코드, 웹, CLI 어디서든 실행
4. **품질 보장**: 자동 검증 + 재시도로 일관된 산출물 품질
5. **Claude Code 생태계 활용**: 바퀴 재발명 않고 네이티브 기능 위에 구축
